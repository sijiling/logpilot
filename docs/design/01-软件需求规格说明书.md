# LogPilot 软件需求规格说明书

## 1. 产品概述

LogPilot 是供开发者个人使用的智能日志诊断服务。系统输入为 Markdown 运维文档、错误日志、故障问题及可选的服务标识；输出为故障摘要、可能原因、处理步骤、风险提示和引用证据。

## 2. 用户角色

MVP 只有“开发者”一种角色，不实现登录鉴权。系统默认只部署在本地或受信任内网。

## 3. 用户故事

- US-01：作为开发者，我希望上传运维手册，以便 Agent 使用项目内部知识回答问题。
- US-02：作为开发者，我希望粘贴错误日志并得到可能原因和处理步骤。
- US-03：作为开发者，我希望看到 Agent 调用了哪些工具和引用了哪些文档。
- US-04：作为开发者，我希望流式查看诊断过程，避免长时间无反馈。
- US-05：作为开发者，我希望查询历史会话并复盘诊断结果。

## 4. 功能需求

### FR-01 文档上传

- 接受单个 UTF-8 Markdown 文件，最大 2 MiB。
- 标题为空时使用文件名作为标题。
- 以 800 字符为目标长度分块，相邻块重叠 120 字符。
- 对每个分块生成向量并写入 Qdrant。
- 重复上传相同 SHA-256 内容时返回已有文档，不重复索引。
- 成功响应包含文档 ID、分块数量和处理状态。

### FR-02 普通诊断

- 请求包含 `session_id`、`question`、可选 `logs` 和可选 `service`。
- `question` 长度为 1—4000 字符，`logs` 最大 64 KiB。
- Agent 可调用 `search_knowledge`、`analyze_log` 和 `check_health`。
- 单次诊断最多调用 6 轮工具；达到上限后必须基于已有证据总结。
- 最终结果包含摘要、可能原因、建议步骤、证据和工具执行记录。

### FR-03 流式诊断

- 与普通诊断使用相同输入。
- 通过 SSE 输出 `session`、`thinking`、`tool_call`、`tool_result`、`answer`、`error` 和 `done` 事件。
- 客户端断开后取消模型和工具调用。
- `answer` 事件可以多次发送文本增量，`done` 只发送一次。

### FR-04 会话查询

- 按会话 ID 返回会话信息及按时间排序的消息。
- 不存在时返回 HTTP 404 和业务错误码 `SESSION_NOT_FOUND`。
- 工具参数中的日志正文和敏感请求头不得原样返回。

### FR-05 知识检索工具

- 使用问题向量查询 Qdrant，默认返回 Top-3。
- 低于相似度阈值 0.55 的结果不作为证据。
- 返回文档 ID、标题、分块序号、摘要和分数。

### FR-06 日志分析工具

- 识别时间、日志级别、错误类型、HTTP 状态码、IP、Go panic 和堆栈首行。
- 对邮箱、IPv4 和疑似密钥进行脱敏后再发送给模型。
- 仅进行文本分析，不读取本机日志文件。

### FR-07 健康检查工具

- `service` 必须来自环境变量配置的服务白名单。
- 只发送 GET 请求，禁止重定向，超时 3 秒，响应体最多读取 4 KiB。
- 拒绝用户直接提交 URL，防止 SSRF。

### FR-08 运行状态

- `GET /healthz` 只检查进程存活。
- `GET /readyz` 检查 SQLite、Qdrant 和模型配置是否可用。
- `GET /metrics` 暴露请求数、延迟、Agent 轮次、工具调用次数和失败次数。

## 5. 非功能需求

| 编号 | 要求 |
| --- | --- |
| NFR-01 | 使用 Go 1.23 或更高版本，服务采用 Gin。 |
| NFR-02 | 所有外部调用必须使用 `context.Context` 和明确超时。 |
| NFR-03 | 同时执行的诊断请求最多 10 个，超出返回 429。 |
| NFR-04 | 请求日志使用结构化 JSON，包含 request_id、session_id、duration 和 status。 |
| NFR-05 | API Key 只从环境变量读取，禁止写入日志和数据库。 |
| NFR-06 | 服务收到终止信号后停止接收新请求，并在 15 秒内完成优雅停机。 |
| NFR-07 | 核心领域与应用层自动化测试覆盖率不低于 70%。 |
| NFR-08 | 单元测试不依赖真实模型、Qdrant、网络或时间。 |
| NFR-09 | Agent 编排使用 CloudWeGo Eino；业务代码不得重复实现通用 ReAct 状态机和模型协议。 |

## 6. 业务规则

- BR-01：Agent 的输出是辅助建议，不宣称已经修复故障。
- BR-02：知识检索结果为空时必须明确说明缺少内部依据。
- BR-03：模型输出不得伪造未发生的工具调用或文档引用。
- BR-04：工具执行失败不终止整个诊断，Agent 可以使用其他证据继续总结。
- BR-05：请求取消后不得继续后台生成或写入诊断结果。

## 7. 验收标准

1. 上传同一文档两次只产生一份索引记录。
2. 提交包含 Go panic 的日志后，响应能识别 panic 和堆栈首行。
3. 知识库包含对应手册时，响应引用正确文档标题和分块。
4. 配置服务白名单后，Agent 可调用健康检查；未配置的服务被拒绝。
5. SSE 客户端能够按顺序收到工具事件、答案增量和完成事件。
6. 模拟模型持续请求工具时，第 6 轮后系统停止循环并返回总结。
7. 客户端取消请求后，模型 Mock 收到 Context 取消信号。
8. `go test ./...`、`go test -race ./...`、`go vet ./...` 和 `golangci-lint run ./...` 均通过。
