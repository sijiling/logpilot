# LogPilot 测试计划

## 1. 测试目标

验证业务正确性、Agent 循环边界、外部依赖失败处理、SSE 协议、数据一致性与安全限制。测试优先覆盖能够造成错误结论、资源泄漏或安全问题的路径。

## 2. 测试层级

| 层级 | 范围 | 外部依赖 |
| --- | --- | --- |
| 单元测试 | 分块、脱敏、日志解析、Agent 状态机、参数校验 | 全部使用 Fake/Mock |
| 组件测试 | SQLite Repository、HTTP Adapter、SSE Encoder | 临时 SQLite、`httptest.Server` |
| 集成测试 | 文档上传到检索、诊断完整链路 | Docker Qdrant + Fake 模型 |
| 冒烟测试 | Compose 启动、健康检查、示例诊断 | 本地容器环境 |

## 3. 核心测试用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| UT-01 | Markdown 含多个标题和超长段落 | 分块不超过目标上限，顺序和重叠正确 |
| UT-02 | 同一内容重复上传 | 第二次不调用 Embedder 和 VectorStore |
| UT-03 | 日志含邮箱、IP、Bearer Token | 进入模型和数据库前均被脱敏 |
| UT-04 | Fake ChatModel 连续返回工具调用 | Eino 在 MaxStep=6 时终止执行 |
| UT-05 | 模型调用不存在工具 | Eino 返回可观察错误，不发生 panic |
| UT-06 | 工具参数不是合法 JSON | Eino 工具绑定返回参数错误 |
| UT-07 | Context 取消 | Eino Agent、ChatModel 和工具均及时退出 |
| CT-01 | SQLite 会话写入事务失败 | 消息和诊断均不出现部分写入 |
| CT-02 | 健康检查目标不在白名单 | 不发出网络请求并返回拒绝结果 |
| CT-03 | 健康检查返回超大响应 | 最多读取 4 KiB |
| CT-04 | SSE 正常执行 | 事件顺序为 session→工具事件→answer→done |
| CT-05 | SSE 中途失败 | 发送 error 后发送 done，连接关闭 |
| IT-01 | 上传手册后提问 | Top-3 包含对应文档分块 |
| IT-02 | Qdrant 写入中途失败 | 文档为 failed 且无残留 Point |
| IT-03 | Fake 模型完成两次工具调用 | 保存完整工具轨迹与最终答案 |
| ST-01 | 11 个并发诊断请求 | 最多 10 个执行，至少 1 个返回 429 |

## 4. Agent 评测集

在 `testdata/eval/cases.jsonl` 保存 10 个固定问题。每条包含 `question`、`logs`、`expected_document_id` 和必须出现的诊断关键词。评测程序统计：

- Retrieval Hit@3：目标不低于 80%。
- Tool Selection Accuracy：目标不低于 80%。
- Required Keyword Recall：目标不低于 80%。

评测结果用于项目说明，不将非确定性的模型评测放进普通单元测试门禁。

## 5. 质量门禁

```bash
gofmt -w .
go vet ./...
golangci-lint run ./...
go test ./...
go test -race ./...
go test -coverprofile=coverage.out ./internal/...
go tool cover -func=coverage.out
```

合并条件：命令全部通过；核心领域与应用层语句覆盖率不低于 70%；不存在未解释的 `//nolint`；密钥扫描无发现。

## 6. 验收流程

1. 执行全部质量门禁。
2. 执行 `docker compose up --build -d`。
3. 确认 `/healthz` 与 `/readyz` 返回 200。
4. 上传 `testdata/runbooks/go-panic.md`。
5. 使用普通接口完成一次诊断。
6. 使用 SSE 接口完成一次诊断并保存终端输出。
7. 查询会话，确认消息与工具轨迹可回溯。
8. 导出 Prometheus 指标并截取演示图。
