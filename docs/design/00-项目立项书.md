# LogPilot 项目立项书

## 1. 项目背景

开发者处理线上故障时，需要在错误日志、历史处理文档和服务状态之间来回查找信息。传统聊天机器人只能根据输入文本回答，缺少工具调用、知识依据和可追踪的诊断过程。

LogPilot 将大语言模型作为推理组件，通过受控工具访问内部知识库与服务健康状态，生成带证据的诊断建议。项目用于学习并展示 Go HTTP 服务、RAG、Agent 工具调用、流式输出、可观测性和容器化能力。

## 2. 项目目标

1. 用户可上传 Markdown 运维文档并建立向量索引。
2. 用户可提交日志或故障问题，获得结构化诊断结果。
3. Agent 可在限定轮次内自主选择知识检索、日志分析和健康检查工具。
4. 用户可通过 SSE 实时查看诊断过程与最终答案。
5. 系统保存会话、工具调用和证据来源，支持回溯。
6. 项目可通过 Docker Compose 在单机环境启动。

## 3. 可行性分析

### 3.1 技术可行性

- Go/Gin 适合实现低依赖 HTTP 服务和 SSE。
- OpenAI 兼容协议可对接云模型或 Ollama，降低模型供应商耦合。
- Qdrant 提供向量写入和相似度检索接口，满足小型 RAG 项目需求。
- SQLite 无需独立数据库进程，适合个人项目保存业务元数据。
- Docker Compose 可统一管理应用、Qdrant 和 Ollama。

### 3.2 进度可行性

项目按 10 个工作日规划。第一个迭代先完成确定性 API 和存储，第二个迭代加入 RAG 与 ReAct，第三个迭代完成流式输出、测试和交付材料。

### 3.3 成本可行性

- 本地开发可使用 Ollama，避免 API 调用费用。
- 云模型作为可选配置，使用者自行提供 API Key。
- 所有基础设施均可本地容器化运行。

## 4. 项目范围

### 4.1 范围内

- Markdown 文档上传、分块、向量化与检索。
- 日志文本解析和常见错误特征提取。
- HTTP 健康检查，只允许访问配置白名单中的地址。
- ReAct 推理循环、工具选择、轮次和超时限制。
- 普通响应与 SSE 流式响应。
- 会话与诊断记录查询。
- 健康检查、结构化日志、Prometheus 指标。

### 4.2 范围外

- 自动登录服务器、执行 Shell 或重启服务。
- PDF、Word、图片等复杂知识文档解析。
- 多用户权限、计费、团队协作。
- 前端管理系统。
- 多 Agent 编排、长期记忆和模型训练。

## 5. 成功指标

| 指标 | 目标 |
| --- | --- |
| 核心 API 可用性 | 演示环境连续运行 2 小时无崩溃 |
| 知识检索 | 预置 10 个问题中 Top-3 命中正确文档不少于 8 个 |
| Agent 可控性 | 单次诊断最多 6 轮、总超时 60 秒 |
| 可追踪性 | 每次诊断均保存工具名、参数摘要、耗时和证据来源 |
| 自动化测试 | 核心领域与应用层语句覆盖率不低于 70% |
| 交付 | `docker compose up --build` 可完成启动 |

## 6. 参考与合规

项目仅参考 [OnCallAgent](https://github.com/yinxiangpingfan/OnCallAgent) 的业务方向，不复制其代码。由于参考仓库未声明许可证，LogPilot 必须独立设计和实现，并在自己的仓库中明确选择许可证。
