# LogPilot 概要设计说明书

## 1. 架构决策

项目采用模块化单体和端口—适配器思想，但不建立复杂的领域层级。业务接口定义在使用方，外部系统通过小接口接入；所有依赖在程序入口手工装配。

```text
HTTP Client
    |
Gin Handler ── SSE Encoder
    |
Diagnosis Service ── Eino ReAct Agent
    |                    |
    |                    +── Model Port ── OpenAI-compatible Adapter
    |                    +── Tool Registry
    |                         ├── Knowledge Search ── Qdrant
    |                         ├── Log Analyzer
    |                         └── Health Checker ── HTTP
    |
Session Repository ── SQLite
Document Service ── Chunker ── Embedder ── Qdrant
```

## 2. 技术选型

| 领域 | 选型 | 理由 |
| --- | --- | --- |
| HTTP | Gin | 与现有技术栈一致，SSE 实现简单 |
| Agent | CloudWeGo Eino ReAct Agent | 复用成熟的模型、工具、流式和中断编排能力 |
| 模型协议 | Eino-Ext OpenAI ChatModel | 对接 DeepSeek OpenAI 兼容 API |
| 文本向量 | 本地特征哈希 | 无额外模型依赖，适合小型运维手册检索 |
| 元数据 | SQLite | 单机部署，无额外数据库容器 |
| 向量存储 | Qdrant | API 清晰，支持元数据过滤与相似度检索 |
| 指标 | Prometheus client | 展示请求、工具和 Agent 运行指标 |
| 日志 | `log/slog` | 标准库结构化日志 |
| 配置 | 环境变量 + 显式解析 | 遵循 12-factor，减少依赖 |
| 测试 | 标准库 `testing` + `testify` | 表驱动测试和断言 |

## 4. 核心接口与框架边界

```go
type Embedder interface {
	Embed(ctx context.Context, texts []string) ([][]float32, error)
}

type VectorStore interface {
	Upsert(ctx context.Context, chunks []VectorChunk) error
	Search(ctx context.Context, vector []float32, limit int, minScore float32) ([]Match, error)
}

type SessionRepository interface {
	Create(ctx context.Context, session Session) error
	AppendMessage(ctx context.Context, message Message) error
	Find(ctx context.Context, id string) (Session, []Message, error)
}
```

模型和工具不再定义项目私有协议：

- 对话模型使用 Eino `model.ToolCallingChatModel`，由 Eino-Ext OpenAI 组件构造。
- 工具实现 Eino `tool.InvokableTool`；工具 Schema、调用参数和结果交由 Eino 传递。
- Agent 使用 `react.NewAgent`，在 `AgentConfig.MaxStep` 中设置最大执行步数。
- 普通诊断调用 `Agent.Generate`，流式诊断调用 `Agent.Stream`。
- 项目只保留 `AgentFactory`，负责组装 ChatModel、业务工具、系统提示和 Callback。

## 5. ReAct 执行流程

1. Handler 校验请求，生成或读取 `session_id`。
2. Diagnosis Service 保存用户消息并构建输入上下文。
3. Eino ReAct Agent 将系统提示、历史消息和工具 Schema 发送给 ChatModel。
4. 如果模型返回工具调用，Eino 校验并分派到已注册的 `InvokableTool`。
5. Eino 将工具结果写回消息上下文并继续下一步推理。
6. 重复步骤 3—5，直到模型返回最终答案、达到 6 轮或 Context 超时。
7. 最终答案和脱敏后的轨迹写入 SQLite。
8. 普通接口返回 JSON；流式接口同步发送 SSE 事件。

退出条件按以下优先级处理：Context 取消、总超时、最终答案、Eino `MaxStep` 上限。工具错误作为一条可观察结果返回模型，不直接触发重试风暴。诊断轨迹由 Eino Callback 收集，业务层不读取或暴露模型隐藏思维链。

## 6. 文档索引流程

1. 校验文件类型、大小和 UTF-8 编码。
2. 计算原始内容 SHA-256，检查重复文档。
3. 按标题和段落边界优先切分；超长段落按字符窗口切分。
4. 批量生成向量，每批最多 16 个分块。
5. 写入 Qdrant；全部成功后再将文档状态更新为 `ready`。
6. 中途失败时文档状态为 `failed`，删除已写入的同文档向量。

## 7. 可靠性设计

- HTTP 服务：读取头 5 秒、读取 10 秒、普通写入 65 秒、空闲 60 秒。
- 模型总超时：60 秒；Embedding 超时：20 秒；Qdrant 超时：5 秒；健康检查：3 秒。
- 并发诊断信号量：10；文档索引信号量：2。
- 所有队列和响应体均有大小上限。
- 关闭顺序：停止接收请求 → 等待在途请求 → 关闭 SQLite 和 HTTP Transport。

## 8. 安全设计

- API Key 仅存在进程环境与请求头，日志过滤 `authorization`、`api_key`、`token`。
- 健康检查只接受逻辑服务名，地址由配置映射；禁止访问环回、链路本地和云元数据地址，除非显式配置为本地开发服务。
- 上传文件只按文本读取，不落盘执行。
- 日志进入模型前脱敏邮箱、IPv4、Bearer Token 和常见密钥格式。
- 模型不能直接调用任意 URL、文件系统或 Shell。

## 9. 可观测性

- 日志字段：`request_id`、`session_id`、`method`、`path`、`status`、`duration_ms`、`tool`、`round`。
- 指标：`http_requests_total`、`http_request_duration_seconds`、`agent_runs_total`、`agent_rounds`、`tool_calls_total`、`tool_duration_seconds`、`document_chunks_total`。
- `/healthz` 不探测依赖；`/readyz` 探测 SQLite 与 Qdrant，模型配置只校验完整性，避免每次探针产生模型费用。
